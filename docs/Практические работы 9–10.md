# Практические работы 9–10 — Учебный планер

## Практическая работа 9. Организация разработки

### Методология

Для индивидуального проекта выбрана итерационная разработка с постепенным наращиванием возможностей. На каждой итерации сохраняется работающий сайт, а функции добавляются небольшими законченными частями. Такой подход подходит проекту одного разработчика: нет необходимости планировать роли команды и ежедневные совещания, а изменения требований можно вносить между итерациями.

Каскадная модель хуже соответствует небольшому учебному проекту: она предполагает более жёсткую последовательность и усложняет возврат к уже завершённым решениям. Итерационный подход позволяет раньше получить работоспособный результат и корректировать его по мере уточнения требований.

| Итерация | Результат |
|---|---|
| 1 | Структура сайта и базовый список учебных задач |
| 2 | Добавление задач с предметом, сроком и приоритетом; сохранение в браузере |
| 3 | Изменение и удаление задач, статусы, фильтрация, поиск и сортировка |
| 4 | Справка в приложении и документация разработчика и пользователя |

Это план и описание инкрементной декомпозиции проекта, а не отчёт о календарных датах каждой итерации.

### Контроль версий и удалённый репозиторий

Для проекта выбраны Git и GitHub. Имя репозитория: `study-planner`. Видимость — публичная, чтобы преподаватель мог открыть проект по ссылке; этот выбор подтверждён пользователем. Исходный проект подготовлен как локальный Git-репозиторий. Создание удалённого репозитория и отправка коммита требуют подключения GitHub к рабочей среде.

После подключения GitHub стандартный порядок публикации:

```text
git remote add origin https://github.com/<имя-пользователя>/study-planner.git
git push -u origin main
```

### Инструменты разработки

- **Visual Studio Code** — редактирование HTML, CSS, JavaScript и Markdown.
- **HTML5** — структура пользовательского интерфейса.
- **CSS** — оформление и адаптация интерфейса.
- **JavaScript** — логика задач и встроенной справки.
- **Git** — история изменений и локальный контроль версий.
- **GitHub** — выбранный хостинг удалённого репозитория (публикация ожидает подключения).
- **JSDoc** — формирование API-документации из комментариев в JavaScript.
- **Веб-браузер** — запуск и эксплуатация сайта.

## Практическая работа 10. Документирование разработки

### Документация разработчика

Код `script.js` содержит JSDoc-комментарии: краткое назначение модуля, структуру объекта `StudyTask`, описание функций, их параметров и результатов. API-документация генерируется инструментом JSDoc в HTML. Архив с результатом генерации включён в `docs/api-docs.zip`; исходные страницы находятся в `docs/api/`.

### Документация пользователя

Для пользователя подготовлено руководство `Руководство пользователя.md` и краткая справка внутри самого приложения. Для практической работы 10 выбран вариант встроенной справки; Fandom Wiki не использовалась. Справка доступна кнопкой «Справка» в верхней панели сайта и объясняет добавление, изменение, поиск и фильтрацию задач, а также локальное хранение данных.
